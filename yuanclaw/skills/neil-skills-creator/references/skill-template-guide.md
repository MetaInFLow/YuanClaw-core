## 前言区规范

### 必填字段

**name**（必需）
- 格式：小写字母 + 连字符，例如 `skill-name`
- 禁止使用 `-skill` 后缀
- 长度建议：3-20个字符

**description**（必需）
- 格式：单行文本
- 内容：核心能力 + 触发场景（可列举多个，互不耦合）
- 长度：100-150字符

### 可选字段

**dependency**
- **python**：直接列出包名和版本，格式同 requirements.txt
  ```yaml
  dependency:
    python:
      - requests==2.28.0
      - pandas>=1.5.0
  ```
- **system**：系统级命令（mkdir、chmod等），禁止包含Python包安装命令
  ```yaml
  dependency:
    system:
      - mkdir -p extra-files/input
  ```

## 正文结构

### 1. 任务目标
- 一句话说明Skill用途
- 能力清单（核心功能要点）
- 触发条件（典型用户表达或上下文信号）

**示例**：
```markdown
## 任务目标
本Skill用于系统化构建Agent Skills，通过六步方法论从问题定义到验证迭代，产出完整的Skill文档和模板资源。

### 触发条件
当用户表达以下需求时触发：
- "我想创建一个Skill"
- "需要按方法论构建Agent技能"
```

### 2. 工作流程
- 流程总览（可用流程图或文字描述）
- 核心步骤概览
- 与Reference的链接关系

### 3. 操作步骤
- 每个步骤的详细规范
- 明确由智能体处理还是调用脚本
- 包含输入、处理、输出
- 异常处理说明

**编写原则**：
- 使用祈使语气（"执行"、"创建"、"调用"）
- 步骤编号清晰（1、2、3或Step 1、Step 2、Step 3）
- 每步不超过5行，细节放Reference

### 4. 资源索引
- 用链接指向references/和assets/中的资源
- 说明何时读取（"见[xxx](路径)(何时读取)"）
- 简要说明用途（"用途与参数"）

**示例**：
```markdown
## 资源索引
- **完整方法论**：见 [references/agent-skill-methodology.md](references/agent-skill-methodology.md)（详细步骤、示例、Tips）
- **Skill模板**：见 [assets/skill-template.md](assets/skill-template.md)（可直接使用的空模板）
```

### 5. 质量检查清单
- 输出物的质量标准
- 检查项（用[ ]表示）
- 关键约束和注意事项

**示例**：
```markdown
## 质量检查清单
- [ ] name符合命名规范（小写+连字符）
- [ ] description单行，100-150字符
- [ ] 步骤清晰，有可执行性
```

### 6. 注意事项
- 关键提醒
- 常见陷阱
- 最佳实践建议

### 7. 边界说明
- 能做什么
- 不能做什么
- 适用范围

### 8. 使用示例（可选）
- 2-3个典型使用场景
- 每个示例包含：
  - 功能说明
  - 执行方式（脚本/智能体/混合）
  - 关键参数或指导要点
  - 简单示例

## 编写原则

### 体量控制
- **正文不超过500行**
- 细节拆入references/
- 参考仅一层链接（避免嵌套）

### 语言风格
- 简洁、直接、术语准确
- 使用中文表达
- 命令/路径/文件名用行内代码样式

### 避免重复
- Skill与Reference职责分离
- Skill讲"怎么做"，Reference讲"长什么样"
- 不要在Skill中重复Reference的内容

---

## 常见错误

| 错误类型 | 错误做法 | 正确做法 |
|---------|---------|---------|
| description过长 | 详细描述所有功能和场景 | 单行，100-150字符，核心能力+触发场景 |
| 正文过长 | 把所有细节都写在Skill里 | 细节放Reference，Skill只留核心流程 |
| 嵌套引用 | references/中引用assets/，assets/中再引用 | 仅一层链接：Skill → references |
| 重复内容 | 在Skill和Reference中写相同的规范 | Reference写详细规范，Skill只链接 |
| 缺少边界说明 | 没说明能做什么不能做什么 | 明确边界，避免用户误解 |

## 完整示例

> 注意：本规范用于阶段一（方法论引导）中打磨模板时参考。实际创建 Skill 文件时（阶段二），由 `skill-creator` 接管，它有自己的 Skill Writing Guide 和最佳实践。本规范帮助你理解 SKILL.md 的结构，以便更好地与 skill-creator 协作。

```markdown
---
name: feature-list-generator
description: 自动将项目方案拆解为功能清单和SOW；适用于售前报价、需求确认、开发依据等场景；支持分步确认和中间层推导
---

# 功能清单生成器

## 任务目标
本Skill用于将项目方案自动拆解为标准化的功能需求清单和SOW工作内容。

## 触发条件
当用户表达以下需求时触发：
- "需要把方案拆解成功能清单"
- "项目报价，需要SOW"

## 工作流程
接收方案 → 评估完整度 → 输出拆解备忘录（中间层）→ 用户确认 → 生成功能清单+SOW

## 操作步骤

### 第一步：接收方案并评估完整度
- 输入：用户提供的项目方案
- 完整 → 进入第二步
- 不完整 → 提问补齐

### 第二步：输出拆解备忘录
- 参考：references/dismantling-memo-template.md
- 输出：拆解备忘录（中间层）

（后续步骤省略...）

## 资源索引
- **拆解备忘录模板**：见 references/dismantling-memo-template.md
- **功能清单模板**：见 references/feature-list-template.md

## 质量检查清单
- [ ] 需求编号格式正确
- [ ] 功能描述具体可验收
- [ ] 优先级分配合理

## 注意事项
- 信息不足时先提问，不要硬拆
- 中间层（拆解备忘录）必须输出

## 边界说明
**能做**：拆解方案为功能清单和SOW
**不能做**：估算工作量和成本
```
